# 言葉帳 · Kotoba-chō

A Japanese vocabulary deck built around a conjugation engine that composes rather
than enumerates. Track words, take any form apart morpheme by morpheme, stack
modifiers the way Japanese actually does, and drill it.

## Running it

```
npm install
npm run dev
```

Then open the URL Vite prints. `npm test` runs the engine regression suite.

## Putting it on a phone

It installs as a PWA — no store, no wrapper, no Android SDK. Everything is
client-side already, so once it is cached the whole app works on a plane.

```
npm run serve
```

That builds and serves on your LAN. Open the **Network** URL it prints on the
phone, on the same Wi-Fi.

- **iPhone** — Share → Add to Home Screen. Works over the plain LAN URL.
- **Android** — needs a public HTTPS URL, no way around it. An Android install
  is a WebAPK, and Google's servers mint it by fetching the manifest and icons
  themselves, so they have to be able to reach the origin. `localhost` and
  `192.168.…` are unreachable to them, and current Chrome no longer offers the
  old plain-shortcut fallback — the menu item is simply absent.

Service workers also need HTTPS (or localhost), so the LAN URL gets you the app
but not the offline cache. Two ways to get HTTPS:

```
npx --yes cloudflared tunnel --url http://localhost:4173
```

A throwaway public HTTPS URL to the machine running `npm run serve` — downloads
the cloudflared binary the first time. Or upload `dist/` to any static host
(Pages, Netlify, whatever) and install from there.

**The URL is public while a tunnel is up.** Build without `VITE_ANTHROPIC_API_KEY`
set — it gets baked into the bundle, so anyone with the URL gets your key. Enter
the key on the phone under Settings instead: it lives in that device's
localStorage, once per device. Everything except lookup and example sentences
works without any key at all.

Once installed over HTTPS the service worker caches the app on first load and it
opens offline from then on. Decks live in that origin's localStorage, so the
phone starts empty — move a deck across with Export / Import JSON.

Icons are generated by `npm run icons` (committed; rerun only if you change the
design in `scripts/make-icons.mjs`).

## What's here

```
src/engine.js   pure logic — conjugation, stacking, the kana IME, answer
                matching. No React, no DOM, no network. This is the valuable
                part and it is independently testable.
src/App.jsx     the React shell: deck, study view, stack builder, quiz.
src/theme.js    palette and type stacks. Colour encodes morpheme class.
src/storage.js  localStorage behind an async interface.
src/speech.js   Web Speech audio with failure reporting.
src/api.js      the two optional network features.
test/           the regression suite.
```

## Features

- **Deck** with furigana / kanji / kana toggle, persisted locally.
- **Vocabulary** — the whole deck as one full-width ledger, meaning-forward,
  filtered by verbs / adjectives / nouns. Verbs and plain words are the same
  store seen at a different distance; a row opens in the deck.
- **Morpheme breakdown** — every form splits into tiles with interlinear glosses
  (`STEM.i`, `POL.NPST`, `NEG.PST`), each tappable for an explanation. Godan
  stems show the 五段 ladder with the active row lit.
- **Stacked forms** — chain causative → passive → たい → negative → past and get
  食べさせられたくなかった with all eight morphemes still individually glossed.
  Available modifiers are gated by the current class, so ます/た/て visibly close
  a chain.
- **Quiz** in two directions: produce a form, or name a form you're shown.
  Answers accepted as kanji, kana, or romaji. Right/wrong tally, missed-item
  drill. **Meaning** questions run alongside, both ways — word to gloss and
  gloss to word, multiple choice with distractors drawn from the rest of the
  deck. It is the only drill a noun has.
- **Kana IME** in the answer field: type `itte`, get いって.
- **Audio** via Web Speech, reading the kana.
- **Export / import** the deck as JSON.

## Known limitations

**Audio depends on the OS.** Web Speech needs a `ja-JP` voice installed. Windows
has Haruka/Ayumi via Language Settings; macOS has Kyoko. With no Japanese voice
the app says so in the footer rather than failing silently. Recorded audio or a
TTS API is the real fix.

**Lookup and example sentences need an API key.** Enter it under Settings → API
key; it is stored in that browser's localStorage and is not included in Export
JSON. For desktop dev you can instead copy `.env.example` to `.env` and set
`VITE_ANTHROPIC_API_KEY`, but Vite inlines `VITE_*` into the bundle, so that key
ships to everyone who loads the build. Either way the key reaches the browser and
is readable there — a server proxy holding the key is the only real fix. Use a key
you can revoke. Everything else works offline.

**Sentences are generated, not sourced.** For a real build, pull them from
Tatoeba (CC-licensed) or JMdict's `JMdict_e_examp.xml`.

**Word class is guessed on manual entry.** The heuristic can't distinguish 帰る
(godan) from 変える (ichidan) by sound alone, so it's one tap to correct. Sourcing
from JMdict removes the guess entirely: `v5k-s` *is* the 行く irregularity and
`adj-ix` *is* the いい irregularity, as data rather than special cases.

**Fonts are system-dependent.** Yu Mincho on Windows, Hiragino on macOS. Stock
Android has neither and falls back to sans — self-host a subsetted Noto Serif JP
if that matters.

## Where to take it next

Persisting quiz results per (word, form) is the highest-value addition. The
questions are structured, so results aggregate along the *grammar* rather than
the vocabulary: "て-form, ぬ/ぶ/む → んで: 41%" is a diagnosis no flashcard app
can produce. Once that table exists, weighting question selection toward weak
forms is a few lines.
